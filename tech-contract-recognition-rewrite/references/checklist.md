# 交稿前自检清单

按「决定成败 → 必须修 → 建议改 → 顺手改」四级跑。前面的做不完，后面白搭。

---

## 零、决定成败 5 问（不过关就不要交）

1. **要件②三处落点是否齐全？**（按 Aaron 偏好，默认用丝滑化写法，检查的是**实质**不是字样）
   - 术语定义：是否写明该技术方案"**由卖方通过本项目研究开发形成**"、非现有可直接选用
   - 其他约定：是否有"本项目为技术开发""不属于对现有产品的选用、组合或配置"的同义落点（双保险）
   - 技术目标末尾：补的那半句还在不在？（位置最值钱，评审第一眼看到）
   - 核验口径：三处至少能读出"**须经本项目研究开发才能形成**"这一层意思，即为合格；
     若当地登记机构字面检索"尚未掌握"被退回，再把技术目标末尾改回原句式
2. **创新性前是否有防火墙句？** —— "……不属于研究开发过程中的工作方法描述"。没有这句，创新性容易被读成"工作方法很有创意"。
3. **差异对照表过关吗？**
   - 对立面是否具体到某一类工具/产品？（写"传统方式"等于回避）
   - 差异是否落在技术实现要素而非效果？（"由人工变自动"是效果，会掉进服务合同画像）
4. **5 个敏感词是否清零？** 部署 / 实施 / 运维 / 售后 / 服务 —— Word 全文检索。
5. **三张表是否逐字一致？** 成果清单表 ↔ 进度表 ↔ 付款条件表（名称、数量、日期、金额）。

## 零之二、人工修订后专项检查（实测教训，必跑）

人工在 Word 里改稿后会引入一批机器不会犯的错，这一节专门抓它们。

| 检查项 | 典型症状 |
|---|---|
| **要件②是否被误删** | 人工精简时最容易把"订立本合同时尚未掌握"整句删掉。**实测：三处落点（术语定义、其他约定、技术目标末尾）曾被一次性全部删光**，认定力度倒退。改完必须重新数一遍 |
| **编辑残留垃圾串** | 正文出现连续重复的当事人称谓（"委托方委托方""受托方委托方受托方"），或段末多出"受托方委托方"。复制粘贴痕迹，打印出来就会被看到 |
| **编号断裂** | 序号出现 1、3、4、5……（第 2 项被删但编号没重排） |
| **标题被吞进列表** | 用自动编号时，"技术内容"等款标题被并进上一款的项目符号列表，导致全篇编号错位。**要在 Word 里逐款核对编号显示** |
| **计数句与列举项不符** | "包括 A、B、C、D 四个部分"但正文只列了三个（常因两项被顿号连成一个） |
| **指标名称四处一致** | 同一指标在「指标表 / 通用取值规则 / 分项口径 / 成效对比表」四个位置必须同名同值。实测出现"兼容覆盖率 / 合规率 / 合规兼容率"三种叫法，以及表里没有 100% 而口径段却在解释 100% |
| **表名与表列一致** | 正文引用"《研究开发成果的形态与载体清单》"，则该表必须真有"载体形式与数量"列；引用不存在的列等于落空 |
| **两张清单表对齐** | 成果清单表 N 项 ↔ 进度表 N 行，数量与名称要对得上（不要把多项合并成一行） |
| **专有名词拼写** | 操作系统名、术语拼写（实测 Ubuntu 写成 Ubunru） |
| **金额格式** | 千分位错位（实测 1,345,000 写成 1,3450,000）；分项之和 = 合计 |

## 一、P0 必须修

| 项 | 检查点 |
|---|---|
| 要件②措辞 | 见上述第 1 问 |
| 创新性防火墙句 | 见上述第 2 问 |
| 成果一致性 | 每条技术成果的载体都要有源代码吗？第十二条说"含源代码"而清单表里没有 → 矛盾，必改 |
| 交付与清单 | 是否与方法、路线、成果清单三套说法一致？同一成果有两套命名 → 必改 |
| 交叉引用 | 全文搜索"第 X 款""附件一""第六条"等引用，确认被引对象**仍然存在**。常见错误：正文只有 4 款却写"第一条第 6 款" |
| 表格完整性 | 每个单元格是否显示完整？（曾出现末行文字在文档里被截断） |
| 金额验算 | 分项之和 = 合计。（曾出现一位数笔误导致凑不平） |
| 仲裁机构 | 写的是具体机构名称，而不是"买方所在地仲裁委员会"（约定不明可能无效） |
| 验收依据 | 是否指向已删除的附件或"技术协议"？指向不存在的文件 = 验收无据 |

## 二、P1 建议改

- **协作事项写"无"**：会让该条显得空洞 → 补 2～4 条实质内容（指定技术对接人并提供必要配合、提供测试接入条件、参与阶段成果确认、组织专家评审并签订验收报告）。
- **指标缺口径**：只有表没有测试口径 → 100% 类指标必然在验收时扯皮。补齐"分母是什么、基准是什么、怎么算通过"。
- **缺验收判定与复测**：没有"全部满足即合格"的定义，指标再多也没有及格线；没有"整改+复测"路径，任一项差 0.1% 就直接违约。
- **只有效果对比没有技术特征**：会被认定为效率改进而非技术创新 → 补创新性技术特征段。
- **"技术服务"措辞残留**：违约责任里若写"卖方未提供技术服务或服务质量有问题"，会与"技术指导系成果转化辅助事项、不构成独立合同标的"自相矛盾 → 删除该项或改写。
- **风险全部由研究开发人承担**：不符合技术开发风险共担惯例，也会削弱"技术开发"属性 → 改"双方合理分担"。
- **违约金无上限**：日违约金 × 天数 + 解除违约金 + 退款可叠加至远超合同总额 → 加"累计不超过合同额的 __%"。
- **买方一次性提供全部资料**（如"签约后 2 日内"）：实际做不到，等于埋违约口子 → 改分阶段提供。
- **缺限时：** "2 日内提交全套计划"过紧 → 改"5 个工作日内"，并给买方确认加时限。
- **数字与单位**：同一指标在表格、口径段、成效对比表中的数值与单位是否一致（如 200 台、≤3s、≥99.5%）。

## 三、P2 顺手改

- 日期格式统一（同一文档里出现"2026年 2 月 13 日""2026年12 月 31日"三种写法）。
- 错字：**买房 / 买方**；以及示范文本自带的错误（如"查阅**卖方**有关的会计账目"应为买方）。
- 进度表"阶段"列出现重复编号（4、4、4、4）。
- 半角/全角符号混用、"／"与"/"混用。
- 同一指称前后不一致（"成果交付物""技术成果""交付物"三者选一个）。
- Word 自动编号是否正常显示（编号错乱会让所有交叉引用失效）。
- 资料处理条款：涉及敏感信息的，不宜写"各自存档保管"，改为"按买方要求返还或销毁并出具书面确认"。

## 四、最后一步：角色互换读一遍

假装自己是认定登记机构的工作人员，只看第一条，问自己三个问题：

1. 这合同的标的是"研发出某个新东西"，还是"干活、提供服务"？
2. 订立合同时双方手里有这套方案吗？（能不能从文中找到明确表述）
3. 这个成果在技术上有什么是现有技术做不到的？（能不能找到具体对应的技术结构）

三问都能在第一条内找到答案，就过关了。
